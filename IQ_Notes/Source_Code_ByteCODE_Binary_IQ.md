# Source Code vs Bytecode vs Binary Code

> **Example File:** `01_HelloWorld.js`  
> **Code:** `console.log("Hello to PlayWright with AI");`

---

## Comparison Table

| Aspect | Source Code | Bytecode | Binary Code (Machine Code) |
|---|---|---|---|
| **What is it?** | Human-readable text written in a programming language | Platform-independent intermediate representation (V8 Ignition) | Platform-specific instructions the CPU executes directly (V8 TurboFan) |
| **Example** *(for our file)* | `console.log("Hello to PlayWright with AI");` | `LdaUndefined` → `Star r0` → `LdaConstant [0]` → `Star r1` → `CallRuntime [ConsoleLog]` *(conceptual V8 Ignition bytecode)* | `mov rdi, [rax+0x10]` → `call ConsoleLog` → `add rsp, 0x28` *(x86-64 machine code)* |
| **Readable by humans?** | ✅ Yes — designed to be read & written by developers | ❌ No — low-level opcodes read by the virtual machine | ❌ No — raw hex/assembly only, CPU-native |
| **Readable by machines?** | ❌ No — needs to be parsed/compiled first | ✅ Yes — V8 Ignition interpreter reads this directly | ✅ Yes — the CPU fetches & executes these directly |
| **Stage in pipeline** | **Step 1** — you write this in an editor | **Step 2** — V8's Parser + Ignition compiler produce this | **Step 3** — TurboFan JIT compiles hot functions to this |
| **Performance** | N/A (not executable) | ~2–5× slower than native | **Fastest** — runs directly on hardware |
| **Portability** | ✅ Cross-platform — runs anywhere with Node.js | ✅ Cross-platform — same bytecode on any CPU | ❌ Tied to one CPU architecture (x86, ARM, etc.) |
| **File format** | `.js` text file (UTF-8) | In-memory byte array (not stored to disk normally) | In-memory machine code pages (JIT'd at runtime) |
| **Can you save it?** | ✅ Yes — it's the `.js` file you see | ⚠️ Possible via `v8` snapshot flags, but not typical | ❌ Not in standard Node.js — generated & discarded at runtime |
| **Generated by** | You (the developer) in a text editor | V8's **Ignition** interpreter (parse → compile → execute) | V8's **TurboFan** optimizing compiler (hot functions only) |
| **Optimization** | N/A — humans optimize for readability | Minimal — Ignition does fast, non-optimized compilation | **Heavy** — TurboFan applies inlining, type specialization, etc. |

## How It Works (Step by Step)

### 1. Source Code — What You Write

```javascript
console.log("Hello to PlayWright with AI");
```

- Stored as `01_HelloWorld.js` (plain UTF-8 text, ~48 bytes)
- Purely for human readability and maintainability
- **The starting point of all execution**

### 2. Bytecode — What V8's Interpreter Runs

When you run `node 01_HelloWorld.js`, V8's parser builds an AST and Ignition generates bytecode — a sequence of compact opcodes:

| Opcode | Meaning |
|---|---|
| `LdaUndefined` | Load `undefined` into accumulator |
| `Star r0` | Store accumulator to register `r0` |
| `LdaConstant [0]` | Load constant at index 0 (`console.log` function) into accumulator |
| `Star r1` | Store accumulator to register `r1` |
| `CallRuntime [ConsoleLog]` | Call the native runtime function for console logging |

**Why it exists:** Bytecode is **small** (~¼ the size of machine code) and **fast to compile** — letting V8 start executing quickly without waiting for full compilation.

### 3. Binary Code (Machine Code) — What the CPU Actually Executes

If the same function runs many times ("hot"), V8's **TurboFan** JIT compiler replaces the bytecode with **native x86-64 or ARM64 machine code**:

```asm
; x86-64 (conceptual — TurboFan output)
mov    rdi, qword ptr [rbx+0x10]    ; load ConsoleLog function
lea    rsi, [rip+0x1234]             ; load "Hello to PlayWright with AI" string
call   ConsoleLog                     ; invoke C++ runtime
add    rsp, 0x28                      ; clean up stack
ret                                   ; return
```

**Why it exists:** Machine code can be **10–50× faster** than bytecode for hot code paths.

---

## Key Takeaways

1. **You write source code** — easy for humans, impossible for machines.
2. **Bytecode** is a compact intermediate that V8 can interpret quickly — it's the "battery" that gets the car moving.
3. **Binary machine code** is what the CPU actually runs — TurboFan generates it only for "hot" (frequently executed) code.
4. **Modern JS engines use both:** start executing bytecode immediately (fast startup), then JIT-compile hot paths to machine code (fast execution).
