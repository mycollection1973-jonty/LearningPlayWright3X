Promise.all() — Full Research

A complete reference on the Promise.all static method: batching promises, fail-fast behavior, result ordering, concurrency patterns, and QA/Playwright usage.

JavaScript · ECMAScript 2015 (ES6) · Baseline: July 2015

1. What is Promise.all()?

Promise.all() is a static method that takes an iterable (usually an array) of promises and returns a single promise that settles based on all of them.

  • All fulfill → returned promise fulfills with an array of fulfillment values.
  • Any rejects → returned promise rejects immediately with that first rejection reason (fail-fast).
  • It's one of the four promise concurrency methods: all, allSettled, any, race.

2. Syntax

Promise.all(iterable)
PartMeaning
iterableAn iterable such as an array of promises (non-promise values are allowed — see §5).
Return valueA single Promise (see the settle rules below).

Settle rules in detail

InputBehavior
Empty iterable Promise.all([])Already fulfilled with [] — synchronously (the only sync case).
All promises fulfillFulfills asynchronously with an array of values in input order, regardless of completion order.
Any promise rejectsRejects asynchronously with the first promise's rejection reason. Later rejections are ignored (no unhandled-rejection events).
Mixed values & promisesNon-promise values are counted as already-fulfilled slots; the result includes them in order.
Marks everything "handled": the moment you call Promise.all([...]), it attaches handlers to every input promise. Rejections after the first one are swallowed silently — they won't trigger unhandledrejection warnings the way sequential await chains can.

3. Live examples — run them below

Example 1 — basic batching (mixed values)

const p1 = Promise.resolve(3);
const p2 = 42;   // plain value — still counted
const p3 = new Promise(resolve => resolve("foo"));

Promise.all([p1, p2, p3]).then(values => {
    console.log(values);   // [3,42,"foo"]
});
// [3,42,"foo"]

Example 2 — results keep INPUT order, not completion order

const slow = new Promise(res => queueMicrotask(() => res(3)));
const fast1 = Promise.resolve(1);
const fast2 = Promise.resolve(2);
// Completion order: 1, 2, then 3.
// Result order    : 3, 1, 2 (matches the input array).

Promise.all([slow, fast1, fast2]).then(values => {
    console.log(values);   // [3,1,2]
});

Example 3 — fail-fast on the first rejection

const p1 = Promise.resolve("Ok service");
const p2 = Promise.reject(new Error("Server down"));
const p3 = Promise.resolve("Never used");

Promise.all([p1, p2, p3])
    .then(values => console.log(values))
    .catch(err => console.log("rejected:", err.message));
// rejected: Server down

Example 4 — with async/await + destructuring (parallel API smoke test)

function apiCall(name) {
    return new Promise(resolve => resolve(name + ": 200 OK"));
}

async function parallelTest() {
    console.log("Starting of the Test");

    const [auth, user, payment] = await Promise.all([
        apiCall("Auth Service"),
        apiCall("User Service"),
        apiCall("Payment Service")
    ]);

    console.log(auth);
    console.log(user);
    console.log(payment);
}

parallelTest();
// Starting of the Test
// Auth Service: 200 OK
// User Service: 200 OK
// Payment Service: 200 OK

4. The over-awaiting trap & running async functions concurrently

Compare these two versions of the same function: 

// SLOW — steps run one after another
async function getPrice() {
    const choice = await promptForDishChoice();
    const prices = await fetchPrices();  // waits for choice first
    return prices[choice];
}
// FAST — both start immediately
async function getPrice() {
    const [choice, prices] = await Promise.all([
        promptForDishChoice(),
        fetchPrices(),      // runs while user decides
    ]);
    return prices[choice];
}
Pass the CALLS, not the functions. Promise.all([promptForDishChoice, fetchPrices]) does nothing — the elements are plain functions, not promises. You must invoke them: Promise.all([promptForDishChoice(), fetchPrices()]).

5. Non-promise values in the iterable

Any non-thenable value in the array is treated as an already-fulfilled promise and included in the result at its index: 

const p = Promise.all([1, 2, 3, Promise.resolve(444)]);
p.then(values => console.log(values));   // [1,2,3,444]

6. Fail-fast behavior

If any input rejects, Promise.all rejects immediately with that reason — even if the other promises would have succeeded later: 

const p1 = new Promise(res => setTimeout(() => res("one"), 1000));
const p2 = new Promise((res, rej) => rej(new Error("reject")));

Promise.all([p1, p2])
    .then(values => console.log(values))
    .catch(err => console.error(err.message));   // "reject" — immediately
Want to survive failures? Attach .catch() to individual promises before passing them to Promise.all, so they always fulfill: Promise.all([p1.catch(e => fallback), p2.catch(e => fallback)]). For full per-promise status, use Promise.allSettled instead.

8. Promise.all in QA & Playwright

  • Wait for multiple responses before asserting: gather page.waitForResponse() promises and await them in parallel.
  • Parallel API health checks: await Promise.all(endpoints.map(u => api(u))) — all must be green, else the batch fails fast.
  • Combine browser + API results: e.g. read UI state and fetch reference data concurrently, then compare.
const [title, apiState] = await Promise.all([
    page.title(),
    request.get("https://api.example.com/state").then(r => r.json()),
]);

expect(title).toBe("Dashboard");
expect(apiState.status).toBe("healthy");

9. Common mistakes & interview traps

  • Passing functions instead of invoked promises → Promise.all([apiCall]) returns the functions unchanged. Always call: apiCall().
  • Forgetting it's fail-fast → if one endpoint is down, the whole batch rejects; you lose the results of the others.
  • Assuming result order = completion order → results always match the input array's order.
  • Sequential awaits for independent calls → pointless slow-down; use Promise.all for concurrency.
  • Not handling the rejection → the batch rejection becomes an unhandled rejection; always chain .catch() or await inside try/catch.
  • Expecting a single value back → you always get an array; destructure or index it (const [a, b] = await ...).

10. Quick IQ questions (with answers)

Q: What does Promise.all([...]) return?
A: A single Promise. It fulfills with an array of all input fulfillment values (input order), or rejects with the first rejection reason.
Q: What is Promise.all([])?
A: An already-fulfilled promise with value [] — the only input case that settles synchronously.
Q: Do results come back in completion order?
A: No — always in the order the promises appear in the input iterable, regardless of when each one resolves.
Q: One promise rejects and two were still pending. What happens?
A: Promise.all rejects immediately with that rejection reason (fail-fast). The other promises keep running, but their results are ignored and later rejections are silenced.
Q: When would you pick Promise.allSettled over Promise.all?
A: When you need every outcome even if some fail — e.g. collecting per-test results across a suite without aborting on the first failure.
Q: Does Promise.all accept non-promise values?
A: Yes — they're treated as already-fulfilled and included in the result array at their index.
