Promise.race() — Full Research

A complete reference on the Promise.race static method: first-settled-wins semantics, the request-timeout pattern, race vs any, and QA/Playwright usage.

JavaScript · ECMAScript 2015 (ES6) · Baseline: July 2015

1. What is Promise.race()?

Promise.race() is a static method that takes an iterable of promises and returns a single promise that settles with the eventual state of the FIRST promise to settle — regardless of whether that state is fulfillment or rejection.

  • First to settle wins. It doesn't matter if the winner fulfilled or rejected — its exact state is copied to the returned promise.
  • Every other promise is ignored after that (its result is discarded).
  • It's one of the four promise concurrency methods: all, allSettled, any, race.

2. Syntax

Promise.race(iterable)
PartMeaning
iterableAn iterable such as an array of promises (non-promise values allowed — see §4).
Return valueA promise that asynchronously settles with the first settled input's state.

Unique settle rules

InputBehavior
Empty iterable Promise.race([])Returns a promise that is forever pending — it never settles (unique among combinators!).
First settled promise fulfillsReturned promise fulfills with that value.
First settled promise rejectsReturned promise rejects with that reason.
Non-promise / already-settled valuesThe first such value found in the iterable wins the race immediately.
Always asynchronous: unlike Promise.all([]) (which is sync), Promise.race never settles synchronously — even with all inputs already settled, you first see it as pending and it settles one tick later.

3. Live examples — run them below

The runnable examples simulate "slower / faster" with microtask rounds instead of setTimeout, so they produce instant, deterministic output.

Example 1 — the faster promise wins the race

function timer(name, rounds) {
    return new Promise(res => {
        let n = 0;
        (function tick() {
            n++;
            if (n >= rounds) res(name);
            else queueMicrotask(tick);   // 1 round = fast, more = slower
        })();
    });
}

const fast  = timer("two", 1);   // settles after 1 round
const slow  = timer("one", 5);   // settles after 5 rounds

Promise.race([slow, fast]).then(value => {
    console.log(value);   // "two" — both fulfill, but fast is quicker
});
// two

Example 2 — rejection can win the race too

const fastReject = new Promise((res, rej) =>
    queueMicrotask(() => rej(new Error("rejects first"))));

const slowFulfill = new Promise(res =>
    queueMicrotask(() => res("fulfillment comes later")));

Promise.race([fastReject, slowFulfill])
    .then(v => console.log("won:", v))
    .catch(e => console.log("won:", e.message));
// won: rejects first — race doesn't care about the outcome, only the speed

Example 3 — non-promise value wins instantly

const neverSettles = new Promise(() => {});   // pending forever

Promise.race([neverSettles, "non-Promise value"]).then(v => {
    console.log(v);   // the plain value is already "settled"
});
// non-Promise value

Example 4 — fastest endpoint of three wins

function api(name, rounds) {
    return new Promise(res => {
        let n = 0;
        (function tick() {
            n++;
            if (n >= rounds) res(name + ": 200 OK");
            else queueMicrotask(tick);
        })();
    });
}

(async () => {
const winner = await Promise.race([
    api("CDN A", 3),
    api("CDN B", 1),   // fastest — wins
    api("CDN C", 2),
]);

console.log(winner);
// CDN B: 200 OK
})();

4. The classic use case — request timeout

Race a real request against a timer that rejects after the deadline. If the request doesn't finish in time, the returned promise rejects with your timeout error: 

const data = Promise.race([
    fetch("/api"),
    new Promise((resolve, reject) => {
        setTimeout(() => reject(new Error("Request timed out")), 5000);
    }),
])
.then(res => res.json())
.catch(err => showError(err));
No cleanup needed! If fetch wins, the timeout rejection is captured and discarded by Promise.race — it will not bubble up as an unhandled rejection.

5. Non-promise and already-settled values

Values that are already settled (or non-promises, which count as settled) win immediately when found — the first one in iterable order: 

const forever = Promise.race([]);                    // pending forever
const settled = Promise.resolve(100);

Promise.race([forever, settled, "hello"]).then(v => console.log(v));
// 100 — the first settled value found (settled comes before "hello")

6. Clever trick — detect if a promise is pending

Because a non-promise wins the race instantly, you can use it as a "pending" marker: 

function promiseState(promise) {
    const pendingMarker = { status: "pending" };
    return Promise.race([promise, pendingMarker]).then(
        value => value === pendingMarker ? value : { status: "fulfilled", value },
        reason => ({ status: "rejected", reason }),
    );
}

async function inspect(p) {
    const state = await promiseState(p);   // safe — called inside an async fn
    console.log(state);
}
// { status: "pending" } | { status: "fulfilled", value } | { status: "rejected", reason }
This still runs asynchronously (there's no sync way to read a promise's value), but it always fulfills within one tick and never actually waits for the promise to settle.

7. Promise.race vs Promise.any — the critical difference

// race — FIRST SETTLED wins (success or failure)
const p1 = new Promise(res =>
    setTimeout(() => res("one"), 500));
const p2 = new Promise((res, rej) =>
    setTimeout(() => rej("two"), 100));

Promise.race([p1, p2])
    .then(v => console.log("succeeded:", v))
    .catch(e => console.error("failed:", e));
// failed: two  ← rejection was faster
// any — FIRST FULFILLMENT wins, ignores rejections
const p1 = new Promise(res =>
    setTimeout(() => res("one"), 500));
const p2 = new Promise((res, rej) =>
    setTimeout(() => rej("two"), 100));

Promise.any([p1, p2])
    .then(v => console.log("succeeded:", v))
    .catch(e => console.error("failed:", e));
// succeeded: one  ← rejections are skipped

Use race when the first completion matters (e.g. timeout detection). Use any when the first success matters (e.g. redundant endpoints).

9. Promise.race in QA & Playwright

  • Time-box slow operations: race an action against a deadline so a stuck operation fails the test instead of hanging the runner.
  • Fastest response wins: probe the quickest of several mirrors / CDNs.
  • State detection: check whether a background operation still pending before deciding to wait or skip.
const timeoutError = new Promise((_, reject) =>
    setTimeout(() => reject(new Error("Navigation timed out")), 10000));

try {
    await Promise.race([page.goto("https://example.com"), timeoutError]);
} catch (err) {
    console.error("Test aborted:", err.message);
}

10. Common mistakes & interview traps

  • Treating race as "first success" → it's first settled; a fast rejection still wins the race. Use Promise.any for first success.
  • Empty array → returns a forever-pending promise that can silently hang your test suite.
  • Expecting synchronous settlement → race is always asynchronous, even with pre-settled inputs.
  • Thinking race starts the promises → it doesn't; the promises were already running when created. race only watches them.
  • Ignoring losing rejections → they're marked handled by the combinator, so a loser's rejection won't trigger unhandled-rejection warnings — but it's also silently discarded.

11. Quick IQ questions (with answers)

Q: What does Promise.race([...]) return?
A: A single promise that settles with the state of the first input promise to settle — fulfilled if that winner fulfilled, rejected if it rejected.
Q: What is Promise.race([])?
A: A promise that stays pending forever — nothing in the iterable can ever settle it.
Q: Same inputs promise.resolve(1) and promise.reject(err) — which wins?
A: The first one found in the iterable wins the race (both are already settled). Order matters.
Q: Promise.race vs Promise.any?
A: race takes the first settled promise (success or failure); any takes the first fulfilled one and skips rejections until all reject (then AggregateError).
Q: Does Promise.race make faster code?
A: No — the promises all run concurrently already. race only decides which result you observe; it doesn't speed up or cancel the others.
Q: A fast request rejects while a slow one would succeed. What do you get with race?
A: A rejection with the fast request's reason. If you wanted the first success, use Promise.any.
